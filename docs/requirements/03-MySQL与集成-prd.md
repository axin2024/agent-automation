# 可视化 AI 业务自动化平台｜MySQL 数据与集成

## 持久化边界

MySQL 8.4 InnoDB 是本项目业务状态与授权关系的权威存储。租户身份进入业务唯一键与关联检查。媒体、文件、备份或模型大对象允许使用文件或对象存储，库内保存版本化引用、长度、摘要及所有者。派生缓存可从持久记录重新构建。

## 逻辑实体与事实来源

| 业务域 | 核心实体与必要字段 | 写入时必须维持的规则 |
|---|---|---|
| 工作流设计 | flow(tenant,key), graph_rev(flow,rev,digest), edge(rev,ports) | 保存类型化端口、必填字段和错误分支，支持试算样本；发布前诊断引用、不可达节点和非法环。 |
| 连接与凭据 | connector(kind,caps), binding(tenant,env,secret_ref) | 凭据按租户、环境与用途授权，编辑者只看引用，轮换后测试最小操作。 |
| 触发与任务 | trigger_key(flow,source,event), run(flow_rev,key,state) | 输入身份绑定流程版本，分配运行前核对并发与预算；重复输入返回同一运行。 |
| 模型与工具 | model_step(run,prompt_rev), tool_result(node,input_hash,output_ref) | 声明模型能见字段、允许工具和返回结构，缺证时转人审，提取值不得自行扩大动作范围。 |
| 审批与外发 | approval(node,content_hash,actor), delivery(op_key,remote_ref,state) | 审批固定收件人、正文和业务数据版本，任一关键字段变化即需复审，外部发送有稳定业务键。 |
| 运行与恢复 | node_run(run,node,attempt,state), probe(op_key,receipt) | 结果分业务拒绝、暂时故障和结果未知；重跑只处理安全节点，对外副作用先查单。 |
| 模板与发布 | template(graph_rev,manifest), release(flow,active_rev,actor) | 模板嵌入字段契约和夹具，导入需重新绑定本地凭据，活动版本切换不修改在途运行。 |
| 运营与评测 | feedback(node,label,reviewer), cost(run,provider,amount) | 区分人工等待、推理耗时及第三方服务时间。对分类、字段提取、需转人工的结果分别抽检。 |

## 事务、索引与对账

- **身份与约束**　租户＋来源事件键唯一，外发操作键跨尝试稳定，审批按内容摘要绑定。
- **业务索引**　按流程和逻辑时刻查运行，按审批人和到期日查待办，按外部键查回执。
- **数据生命周期**　试跑和生产凭据隔离，正文与计量审计独立设置保留期。

触发键、流程版本、节点与外部操作号持久化。审批仅放行其冻结内容，外部通知经事务待发与回执核对。

列表使用租户、业务状态、更新时间和稳定主键分页。外部事件保留来源、外部号、内容摘要、处理结果和业务对象引用。同键不同内容产生显式冲突；网络超时后按原键查单。跨存储发布应先确认文件持久，再发布其数据库引用；回收须验证没有有效引用。

## 集成契约

邮件、订单、模型、工单与发送端适配器声明输入输出、权限及重试语义。自托管演示邮件送入本地收件箱。

作者发布图版本与节点契约，返回摘要、缺失凭据和不可达分支；运行冻结当时版本。

审批绑定内容摘要和收件端，编辑输出或订单状态失效须重新审查，发送前复核授权。

## 数据恢复与核验

在隔离环境恢复 MySQL 和引用清单，校验样例的源对象、派生关系及最终结果。恢复后应能回答以下问题。只建一个工单，过期草稿需刷新，最终外发一次；发送结果未知进入查单且不自动重发。
