# 可视化 AI 业务自动化平台 2.0 产品需求文档

**长周期业务案件与多角色智能协作**
需求评审版 · 2026-11-26 · 计划基线 v1.1.0（184b26f）

## 产品目标与交付边界

当前发行覆盖可视化流程、工具审批、回执查单与版本回滚。本版支持以下业务流程。一笔售后投诉跨多日经历资料补齐、模型分类、人工调查和授权执行，所有参与者围绕同一案件办理。 [现有项目说明](../../README.md) · [上一版业务需求](02-业务与交互-prd.md)

演示连接器使用本地收件与订单库。角色间通过结构化证据和建议传递信息，审批权限独立于提示词。

## 使用者与工作台

案件主管设模板，调查员补证，复核人提意见，授权人审批，执行连接器返回回执。

案件工作台以时间线串联原始材料、角色意见、批准和外部回执。调查员可从结论跳回引用，主管集中处理逾期、冲突和查单失败。

## 功能需求

下列六项均纳入正式版本。验收编号按项目独立，后文列出每项的触发条件和预期结果。

| 需求 | 模块 | 产品行为与约束 | 验收 |
| --- | --- | --- | --- |
| R1 | 案件模板 | 业务负责人定义阶段、必备证据、办理角色与超时动作，按入口匹配版本。 | A1、A2 |
| R2 | 协作待办 | 分派调查、复核和决策任务，支持并行会签、代办与交接，展示剩余期限。 | A3、A4 |
| R3 | 证据工作区 | 归集客户补件、订单快照与引用片段，标注真实性和可见角色，服务端裁剪模型输入。 | A5、A6 |
| R4 | 角色助手 | 分别生成分类、调查摘要和拟办意见，输出须引用案件证据，记录模型版本与人工修订。 | A7、A8 |
| R5 | 决策与执行 | 按动作类型限额、双人批准、把决定绑定参数摘要，执行端提供业务回执。 | A9、A10 |
| R6 | 督办与复盘 | 按业务日历升级超期案件，比较处理时长与重开率，回放决策链并形成改进样本。 | A11、A12 |

## 页面操作与回执

| 关联需求 | 角色与入口 | 操作细节 | 需要读回的字段 |
| --- | --- | --- | --- |
| R1 · 案件模板 | 案件主管/模板配置 | 配置分流、证据门槛和各阶段 SLA，预演样例 | case_type_rev、required_items |
| R2 · 协作待办 | 调查员/协作队列 | 认领一项调查，转派时写入未完成事项与接手人 | assignment_id、lease_rev |
| R3 · 证据工作区 | 材料管理员/证据台 | 整理授权材料、标明版本并预览各角色可见字段 | evidence_rev、allowed_fields |
| R4 · 角色助手 | 复核人/意见工作区 | 对比两角色结论和引用，保留人工修订差异 | proposal_id、citations |

每次下发动作前重新验证案件轮次、证据版本、批准人与请求摘要。并行会签使用独立账号，每份决定最多有一个成功执行回执。

## 状态、权限与数据

案件 新建→调查→待补件或待会签→待执行→待核对或已办结。重开生成新处置轮次。

人工和模型操作分开署名，模型没有签核权。所有执行动作以案件轮次和决定版本为业务键。

MySQL 保存业务记录与操作回执。下列为新增逻辑对象和关键字段，所有归属组织的数据都须持有可校验的组织标识。

- `case_record(type,subject,deadline)`
- `task_assignment(role,lease)`
- `evidence_item(source,digest)`
- `proposal(action,args_hash)`
- `decision(actor,scope,expiry)`

并行任务按角色及轮次唯一，变更证据后使依赖原版本的决定失效。 写入前校验操作者对目标对象的权限与当前修订。详情、搜索、导出和后台重试按同一归属校验。保留决定者、请求号、前后状态、发生时间及关联证据编号。

## 核心接口与集成

主要写入入口为 `POST /cases/{id}/decisions`。请求必填字段为 `proposal_id, evidence_rev, args_hash, approval_role`。成功回执提供 decision_id, required_votes, dispatch_state。请求另带租户身份和幂等键。相同键及相同内容返回原业务编号，相同键对应不同内容返回 409。输入不满足业务约束时返回 422 和字段路径，身份无权限读取的跨租户对象返回 404。

需要异步处理时，接收事务同时写入业务记录与待处理事件，再返回 202 及回执查询地址。回读须显示当前状态、已完成步骤、上次失败原因和可重试条件。外部系统已受理但应答丢失时，按原请求身份核查实际结果。

### 合成请求与业务回执样例

请求体示例使用演练环境中的对象。带摘要的样例在开发验收时应替换为实际文件或参数的计算值。

```json
{
  "proposal_id": "P7",
  "evidence_rev": 3,
  "args_hash": "sha256:dddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddd",
  "approval_role": "finance"
}
```

业务回执示例可由提交响应或后续状态查询取得。

```json
{
  "decision_id": "D7",
  "required_votes": 2,
  "dispatch_state": "awaiting_second_vote"
}
```

两票来自同一身份时拒绝第二票，不产生执行任务。批准身份由认证会话确定。

## 升级、部署与恢复

旧流程仍可独立运行。选择一个已发布版本作为案件步骤时引用原定义，历史运行按需关联并去重。 在隔离副本运行迁移预检，输出记录数量、归属冲突和待处理编号。新增结构先部署，回填分批提交并保存游标，完成对账后按租户启用新入口。

演练时在首次成功写入新业务后中断进程，从检查点重启。核对批准摘要、受理回执、重开轮次及待办责任人。需要退出试点时停收新请求，排空已受理操作并导出未决清单。涉及数据恢复时同时恢复数据库与关联证据，再核对外部已生效的动作。

## 编号验收用例

以下均为下一版待执行的验收条件。正常与异常场景使用隔离租户、固定时钟和可重置的合成数据。

| 编号 | 需求 | 操作与可观察结果 |
| --- | --- | --- |
| A1 | R1 · 案件模板 | 同客户两个不同诉求建立独立案件。 |
| A2 | R1 · 案件模板 | 同一外部单号换内容触发冲突复核。 |
| A3 | R2 · 协作待办 | 两个部门会签完成后只进入一次决策阶段。 |
| A4 | R2 · 协作待办 | 被撤销的代办身份不能提交旧任务。 |
| A5 | R3 · 证据工作区 | 模型只收到已授权的订单字段及去标识摘要。 |
| A6 | R3 · 证据工作区 | 补件版本替换后旧建议标记须复审。 |
| A7 | R4 · 角色助手 | 同一案件两角色得到不同可见材料并引用正确来源。 |
| A8 | R4 · 角色助手 | 建议包含不存在的订单或引用时退回人工处理。 |
| A9 | R5 · 决策与执行 | 批准 100 元额度后仅允许执行一次对应动作。 |
| A10 | R5 · 决策与执行 | 修改收款对象后原批准立即失效。 |
| A11 | R6 · 督办与复盘 | 周末暂停计时的案件周一到期时仅通知一次。 |
| A12 | R6 · 督办与复盘 | 重新开案保留原决定、重新授权和后续执行两段记录。 |
| A13 | 全流程 | 用 30 个新合成案件跑真实本地模型，其中 10 个证据不足。公布引用准确率、转人工数、人工采纳及用量，未经批准的执行数必须为零。 |
| A14 | 容量与可靠性 | 1 万个开放案件、每秒 50 次事件，待办视图 P95 ≤ 800 ms，重复通知造成的额外外发为零。 |

负载报告须记录机器及依赖版本、预热和采样时长、成功数、拒绝数和超时数。验收人从工作台与业务记录两侧核对 A13，并附上原始输入、回执和最终状态。真实模型、人工判断和回放夹具分别出具结果，记录模型及权重版本、输入规模、失败样本与资源消耗。

### A13 模型评测

预先标记证据支持的结论和缺失字段。10 个资料不足的案件都必须停在待补件或人工处理。逐案比对引用及执行回执。报告人工改稿前后的准确率。

## 分期交付

1. **案件模型和协作。** 交付可导入的样例和可读回的第一批业务对象，验证基础身份、归属及版本。
2. **证据与角色助手。** 串通参与角色和执行入口，演练并发、重复请求及部分成功后的恢复。
3. **受控执行和督办。** 完成全流程验收、容量实测和旧版升级。随开源发行提供中文配置、样例输入输出、备份恢复步骤及已知限制。
